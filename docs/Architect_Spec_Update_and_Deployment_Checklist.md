# SkillForge AI Coach: Architectural Spec Update & Deployment Checklist

## Overview
This document outlines the recent architectural modernization of the SkillForge AI Coach, targeting GFS (Google Field Sales) Architects for review. The updates transition the system from monolithic prompt-based architectures to a scalable, multi-agent system built on the ADK 2.0 specification, utilizing the latest Gemini 3.1 models and Agent-to-UI (A2UI) rendering.

---

## 1. Architectural Updates (Spec Doc)

### 1.1 Model Upgrades (Gemini 3.1 Family)
All backend inference endpoints have been upgraded to leverage the Gemini 3.1 family of models:
- **`gemini-3.1-live`**: Deployed on the `gemini-api` endpoint for real-time, low-latency conversational coaching.
- **`gemini-3.1-flash`**: Deployed across all background processing and workflow agents (`ai-subject-wizard`, `discover-resources`, `learning-path-ai`, `prompt-engineering-ai`, `vertex-ai`) for cost-effective, high-throughput logic execution.

### 1.2 ADK 2.0 Multi-Agent Orchestration
We replaced the single-prompt monolithic scenario generation with a distributed **ADK 2.0 Multi-Agent Team** using a Sequential Workflow. The new endpoint is `adk-course-creator`, which orchestrates three distinct agent roles:

1. **CurriculumArchitect Agent**
   - **Responsibility:** Ingests user role, industry, and skill level to design a pedagogical syllabus structure.
   - **Output:** Strict JSON Syllabus outline.
2. **ContentWriter Agent**
   - **Responsibility:** Acts as the Subject Matter Expert, expanding the syllabus into comprehensive lessons, scenarios, and challenge questions.
   - **Tools:** Equipped with **Google Search Grounding** via Vertex AI to retrieve real-time documentation and facts.
   - **Output:** Strict JSON Educational Content payload.
3. **A2UIBuilder Agent**
   - **Responsibility:** Frontend mapping specialist that translates raw educational text into an A2UI component tree.
   - **Output:** Strict JSON A2UI blueprint.

### 1.3 Agent-to-UI (A2UI) Dynamic Rendering
The frontend has been decoupled from rigid data models (`{ tasks: [] }`) to support generic A2UI JSON payloads.
- **`Catalog.tsx` Expanded:** Added support for layout components (`Accordion`, `Tabs`, `Card`) and interactive elements (`Checkbox`, `RadioGroup`, `Textarea`).
- **`DynamicLessonViewer.tsx`:** Universal renderer deployed inside the `ScenarioWorkflow`. It securely parses the A2UI JSON payload and mounts native React/shadcn components dynamically. Legacy scenarios automatically fall back to the old UI layout to prevent data loss.

## 2. Deployment Checklist

### Pre-Deployment
- [ ] **GCP Vertex AI Quotas:** Verify that the GCP project has sufficient quota for the `gemini-3.1-flash` and `gemini-3.1-live` models in the deployed region (`us-central1`).
- [ ] **Vertex AI Search Grounding:** Ensure Vertex AI Google Search Grounding capabilities are enabled for the project to support the `ContentWriter` agent.
- [ ] **Dependency Verification:** Verify that `@google-cloud/vertexai` is up-to-date in the `functions/` directory to support the new model families.

### Edge Functions Deployment (Supabase / GCP)
- [ ] Deploy `functions/discover-resources`
- [ ] Deploy `functions/prompt-engineering-ai`
- [ ] Deploy `functions/vertex-ai`
- [ ] Deploy `functions/learning-path-ai`
- [ ] Deploy `functions/ai-subject-wizard`
- [ ] Deploy `functions/gemini-api`
- [ ] Deploy the **NEW** orchestration function: `functions/adk-course-creator` (Ensure the `shared/agents/` modules are bundled successfully).

### Frontend Deployment (Vite/React)
- [ ] Build the frontend (`npm run build:dev` -> `npm run build:prod`).
- [ ] Verify `DynamicLessonViewer` and expanded `Catalog` components are included in the bundle.
- [ ] Deploy the static assets to the frontend hosting environment.

### Post-Deployment Verification
- [ ] **Real-Time Coaching Test:** Open the AI Coach chat and confirm responses are streaming successfully from `gemini-3.1-live`.
- [ ] **ADK Course Creator Test:** Initiate a new learning scenario generation. Verify that the UI transitions to the loading state and successfully mounts the dynamic A2UI components (Tabs, Accordions) generated by the multi-agent team.
- [ ] **Search Grounding Test:** Request a scenario about a very recent software update or event. Verify the `ContentWriter` correctly retrieves and includes grounded, up-to-date information in the lesson.
- [ ] **Backward Compatibility Test:** Open an older, pre-existing scenario from the database. Verify that it still loads cleanly using the fallback legacy UI view.
